How to export alerts from SolarWinds DPA

Option A — Native JSON export (recommended): In the DPA web console, go to Alerts → Alert Configuration. Click the Export button (top-right) to download the alert definitions as JSON files (Alerts_*.json, Rules_*.json, CustomProperties_*.json). Drop all three files onto this tool — or just Alerts_*.json for alert definitions only. This format captures alert names, types, active state, execution intervals, thresholds, and parameters.

Option B — Alert history CSV: Navigate to Alerts → Alert History on the instance you want to export. Use the date range picker to select your time window, then click Export to CSV in the top-right of the alert table. The exported file includes columns: AlertName, Severity, DatabaseInstance, StartTime, AlertType, Message, Threshold, CurrentValue. Severity levels map as: Fatal → High, Critical → High, Warning → Medium, Informational → Low.

DPA-specific alert types with no Redgate Monitor equivalent: DPA Monitor Error, DPA Resource Collection Error, and Round-trip Time Probe are internal DPA health alerts that cannot be recreated — they will be flagged as Not Available in the mapping. Wait Time Anomaly and Query Throughput Anomaly alerts require Redgate Monitor v14+ Dynamic alerts for the closest equivalent.

How to export alerts from IDERA SQL Diagnostic Manager

In the SQLdm desktop client, open the Alert Browser (left panel under the monitored instance). Right-click the alert list and choose Export to CSV, or go to File → Export → Alerts. The exported file will include columns such as SQLServer, Alert, Severity, Category, Date/Time, Current Value, Threshold, and Details. You can also export from the SQLDM Repository database directly by querying SQLdmRepository.dbo.Alerts. Severity levels map as: Critical → High, Warning → Medium, Informational → Low.

How to export alerts from SQL Sentry

In the SQL Sentry client, open the Alerts log view. Arrange the columns you want (recommended: Target, Name, Type, Condition Type, Severity, Start Time, End Time, Duration, Notes), then go to File → Export Data, choose CSV, and save. The tool auto-detects SQL Sentry column names including Target (maps to database instance) and Notes (maps to message/description). Remap any column that doesn't auto-detect in step 2.

How to export alarms from Quest Spotlight on SQL Server

Spotlight Enterprise (on-premises): Open the Spotlight web console or desktop client. Navigate to History → Alarm History and set the desired date range. Right-click the alarm grid and choose Export → Export to CSV, or use the Download icon above the grid. The exported file includes columns: Connection (monitored server), Alarm (alarm name), Severity, Raised (start time), Resolved (end time), Status, Value (current value), and Threshold. Severity levels map as: Critical → High, High → High, Medium → Medium, Low → Low, Informational → Low.

Spotlight Cloud: Log in at spotlightcloud.io. Go to Alarms → Alarm History, filter by connection and date range, then use Export to CSV. Column names match the on-premises export.

Spotlight-specific alarms with no Redgate Monitor equivalent: Performance Investigator and Poor Performance Health are Spotlight-proprietary composite scores — no T-SQL equivalent exists. Monitored Server — * alarms are internal Spotlight connectivity/collection health alarms that cannot be recreated. LiteSpeed Backup alarms require Quest LiteSpeed to be installed. Tempdb File Location, Tempdb Growth Settings, and Tempdb Number of Files are configuration-audit alarms that fire once when misconfigured — enforce via policy/DSC rather than ongoing alerting.

Threshold unit differences to note: Spotlight "Backup — Days Since Last Full Backup" is in days → multiply × 24 for Redgate Monitor's hours. Spotlight memory alarms use % — convert to MB available (total_RAM_MB × (1 − pct/100)). Disk "Percentage Used" maps directly to Redgate Monitor "Disk Used %".

How to run the PowerShell script

1. In your Redgate Monitor portal go to Configuration → PowerShell API and download the module + generate an auth token.
2. Place RedgateSQM.psm1 in the same folder as the generated .ps1.
3. Run: .\alert_to_redgate.ps1 on any machine that can reach your Redgate Monitor server.
4. Alerts appear as timeline annotations on each matched SQL instance.
5. Alerts marked [CUSTOM METRIC REQUIRED] need a custom metric built first under Configuration → Custom metrics and alerts.
